# ADR-027：V2.3 固定版本内容提取与本地搜索 / V2.3 Fixed-Revision Content Extraction and Local Search

- 状态：已接受（D127-A–D132-A） / Status: Accepted (D127-A–D132-A)
- 日期：2026-10-10 / Date: 2026-10-10
- 依据：[V2.3 决策门](../application/PIG-V2.3-decision-gate.md)与[当前范围](../project-rules/CURRENT_SCOPE.md) / Basis: [V2.3 gate](../application/PIG-V2.3-decision-gate.md) and [current scope](../project-rules/CURRENT_SCOPE.md)

## 决定 / Decision

1. 首批仅交付 TXT、CSV、EML、XLSX；PDF、DOCX、PPTX 返回 `UNSUPPORTED`，待真实且
   获授权的 Fixture、定位、许可证、性能与 Windows 包装评估后，单独批准运行时依赖。
2. 用户选择 `READY` Context Revision 才提取。`ExtractionRun` 保存固定 Revision、输入
   SHA-256、Extractor 版本、配置 Hash、状态和安全错误码。同键成功结果复用；失败可重试。
3. 单次解析在受控子进程中运行。父进程先校验 Context Object，子进程再次核对 SHA-256；
   输入 64 MiB、输出 32 MiB、最多 10,000 元素、单元素 4,000 字符、超时 45 秒。
   这是有界故障隔离，**不是 OS 安全沙箱**；Windows 内存峰值尚需打包实测。
4. `ContentDocument` 与有序 `ContentElement` 是项目内 Canonical Content；Locator 的类型
   为 LINE、CSV_ROW、EMAIL_FIELD 或 SHEET_CELL。FTS5 是同一 SQLite 内的派生索引，
   可从元素重建，不充当版本事实。中文短语目前使用受控的本地子串查询补充 FTS5。
5. 搜索返回固定 Revision、片段和 Locator。打开时生成原文件名的只读项目内预览副本；
   Host Application 不承诺自动跳页/单元格。预览被外部修改后拒绝覆盖，不回写 Revision。
6. EML 在 Workbench 中是 Container View；仅对 EML 增加 Context 捕获入口，捕获原邮件
   来源字节。ZIP/RAR/7z 等 Container 仍不能作为 Context Item 加入。

1. The first batch covers TXT, CSV, EML, and XLSX only. PDF, DOCX, and PPTX return
   `UNSUPPORTED` until authorized real fixtures, location accuracy, licensing, performance,
   and Windows packaging are evaluated and any runtime dependency is separately approved.
2. Extraction requires an explicitly selected `READY` Context Revision. Each `ExtractionRun`
   records the fixed Revision, input SHA-256, extractor/configuration versions, state, and safe
   error code. Equivalent successful runs are reused; failures can be retried.
3. A one-shot child process performs parsing. The parent verifies the Context Object and the child
   checks its hash again. Limits are 64 MiB input, 32 MiB output, 10,000 elements, 4,000 characters
   per element, and 45 seconds. This bounds failures but **is not an OS sandbox**; packaged Windows
   peak memory still needs measurement.
4. Ordered `ContentElement` rows are canonical; typed locators are LINE, CSV_ROW, EMAIL_FIELD, and
   SHEET_CELL. In-project SQLite FTS5 is derived and rebuildable. A bounded-page local substring
   query supplements FTS5 for short Chinese phrases.
5. Search shows fixed Revision, snippet, and locator. Opening creates a read-only project-owned
   preview using the original file name; host-app page/cell jumps are not promised. A modified
   preview is never overwritten or written back to the Revision.
6. EML is a Workbench Container View, so Context capture is extended only for the original EML
   source bytes. ZIP/RAR/7z containers remain ineligible as Context Items.

## 数据与恢复 / Data and recovery

正文与 FTS5 倒排索引保存在 `project.sqlite`，因此数据库和后续备份含敏感正文；用户在提取
前获得明确告知。状态与 Event 同一数据库事务写入，Event 只存计数和安全码、不存正文。
子进程临时 JSONL 位于项目 `.staging/content`，仅清理本次操作拥有的目录；异常中断后的
`RUNNING` 记录需用户确认无任务运行后显式标记失败并重试。索引表丢失时可从 Canonical
Element 重建，不触碰 Original、Working、Context Object 或 Context Pack。Schema 使用
`0014_content_search` 前向迁移；既有项目遵守备份、确认和事实校验升级。

Text and the FTS5 inverted index reside in `project.sqlite`, so that database and later backups
contain sensitive text; users see an explicit notice before extraction. State and Events commit
together, and Events contain counts/safe codes only. Operation-owned temporary JSONL lives under
`.staging/content`; interrupted `RUNNING` rows require a user-confirmed recovery after ensuring no
active worker remains. The index can be rebuilt from canonical elements without touching Original,
Working, Context Objects, or Context Packs. Existing projects upgrade forward to `0014_content_search`
only through the confirmed backup-and-validation path.

## 非目标 / Non-goals

当前不引入 Docling、OCR、LLM、RAG、Vector DB、自动全 Workspace 索引、Host Application
深链接或多实例并发写入。复杂格式的候选评估单独记证据，不将提案等同交付。

No Docling, OCR, LLM, RAG, vector DB, automatic whole-Workspace indexing, host-app deep links,
or multi-instance concurrent writes are included. Candidate complex-format evaluations are
recorded separately and are not equivalent to a shipped implementation.
