# ADR-026：V2.2 Context Pack 交付决策 / V2.2 Context Pack Delivery Decisions

- 状态：已接受 / Status: Accepted
- 日期：2026-10-08 / Date: 2026-10-08
- 决策：D120-A 至 D126-A / Decisions: D120-A through D126-A
- 上位约束：`ADR-010`、`ADR-024`、`ADR-025` / Parent constraints: `ADR-010`, `ADR-024`, `ADR-025`

## 背景 / Context

V2.1 的 Context Item、Section、人工说明与不可变 Revision 已可在单个 Project 中
持久化，但仍不能可靠交接给另一台机器。V2.2 交付离线、可验证、平台无关的 Context
Pack；不实施内容解析、AI、厂商连接、双向同步或 Container 回写。

V2.1 persists Context Items, Sections, human guidance, and immutable Revisions
inside one Project, but cannot yet hand them off reliably to another machine.
V2.2 delivers an offline, verifiable, vendor-neutral Context Pack. It does not
implement content extraction, AI, vendor connectors, bidirectional sync, or
Container write-back.

## 决策 / Decisions

1. **D120-A**：V2.2 同时支持目录包和 ZIP 包；先完成目录核心，再复用同一 Pack Plan
   实现 ZIP。用户明确选择输出格式。
2. **D121-A**：默认采用 Active Item 的当前 READY Revision；允许逐 Item 显式选择
   仍可用的历史 READY Revision，并在 Export Entry 中固定。
3. **D122-A**：概览由 Project 名称、Section、Item 用途和人工 Annotation 确定性生成。
   模板双语，用户原文不自动翻译；不新增项目级自由文本字段，不生成业务结论。
4. **D123-A**：每个 Item 的选定字节只在 `files/` 下保存一份；稳定 ID 与安全文件名
   构成相对路径，多 Section Placement 在 Manifest 和概览中显式表达。
5. **D124-A**：`WORKSPACE_UPDATED` 警告后可经用户确认导出固定 Revision；缺失或
   Hash 不匹配的 Context Object 必须阻断，不回退到 Working 或 Original。
6. **D125-A**：目标必须在 Project 受管目录外；目标已存在则失败，不覆盖或自动改名。
   同目标卷 staging、校验后原子发布，失败/取消清理 staging。
7. **D126-A**：持久化 Export 和 Entry 历史；成功包的 Revision 引用受保留保护。预检
   产生一次性计划 Token，执行时重验 Context Revision、Entry、容量和目标；失败/取消
   不伪装成功，也不生成无效保护引用。

1. **D120-A**: Support both directory and ZIP packs in V2.2. Deliver directory
   core first, then reuse one Pack Plan for ZIP. The user explicitly selects
   the output format.
2. **D121-A**: Default to each active Item's current READY Revision; permit an
   explicit per-Item choice of another available READY Revision and freeze it
   in Export Entries.
3. **D122-A**: Generate the overview deterministically from Project name,
   Sections, Item purposes, and human Annotations. The template is bilingual;
   user text is not translated. Add no project-level free-text field or invented
   business conclusions.
4. **D123-A**: Store selected bytes once per Item under `files/` using a stable
   ID and safe name. Express multiple Section Placements explicitly in the
   manifest and overview.
5. **D124-A**: Warn on `WORKSPACE_UPDATED` and allow explicit confirmation of
   the fixed Revision. Missing or hash-mismatched Context Objects block export;
   never fall back to Working or Original bytes.
6. **D125-A**: Destination lies outside managed Project storage. Existing
   targets fail without overwrite or silent rename. Stage on the destination
   volume, verify, atomically publish, and clean staging on failure/cancel.
7. **D126-A**: Persist Export and Entry history; successful-pack Revision
   references protect retention. Preflight creates a one-use plan token;
   execution revalidates Context Revision, Entries, capacity, and destination.
   Failed/cancelled exports never appear successful or create invalid protection.

## 后续路径修订（2026-10-12） / Later path revision (2026-10-12)

产品负责人在 V2.4 人工验收中明确要求目录包的 `files/` 下一层直接是可读文件名。
因此 D123-A 的“稳定 ID 目录”部分被本次授权取代：现行导出使用
`files/<安全文件名>`；同名（含大小写差异）按所选 Item 顺序生成
`名称 (2).扩展名` 等可读后缀。Item ID、固定 Revision ID 和最终相对路径仍在
Manifest 与导出历史中显式保存；相同文件名不覆盖，旧导出包不改写。

During V2.4 manual acceptance, the owner requested human-readable filenames directly under
`files/` in directory packs. This supersedes the stable-ID-directory part of D123-A for new
exports: use `files/<safe filename>`, with readable ` (2)`-style suffixes for collisions,
including case-insensitive names, in selected-Item order. The manifest and export history
still carry Item ID, fixed Revision ID, and final relative path. No names overwrite each
other and previously exported packs are not rewritten.

## 实施授权 / Implementation authorization

用户已批准 D120-A 至 D126-A 并明确进入 **V2.2.1 Contract + Schema**。本阶段只创建
领域契约、Migration、Mapping、Repository 与只读 Pack Plan 查询及测试；不发布目录或
ZIP，不增加 UI。V2.2.2–V2.2.4 仍需逐段进入。

The user approved D120-A through D126-A and explicitly entered **V2.2.1
Contract + Schema**. This stage only creates domain contracts, migration,
mappings, repositories, a read-only Pack Plan query, and tests. It publishes
neither directory nor ZIP and adds no UI. V2.2.2–V2.2.4 require separate entry.

后续授权记录（2026-10-09）：产品负责人明确要求一次性完成整个 V2.2；因此
V2.2.2–V2.2.4 的目录/ZIP 发布、最小 UI 与合成数据验收已获授权。此授权不扩展至
真实资料自动读取、异机人工验收、内容解析、AI 或 V2.3。

Subsequent authorization (2026-10-09): the product owner explicitly requested
completion of all V2.2 in one task. Directory/ZIP publication, minimum UI,
and synthetic-data acceptance in V2.2.2–V2.2.4 are therefore authorized.
This does not authorize automatic use of real materials, cross-machine manual
acceptance, content extraction, AI, or V2.3.
