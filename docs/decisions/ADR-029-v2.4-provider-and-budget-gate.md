# ADR-029：V2.4 Provider 与预算 Gate / V2.4 Provider and Budget Gate

- 状态：已接受（D143、D144–D146）；真实 Provider 资格与业务资料外发尚未签收 / Status: Accepted (D143, D144–D146); live provider qualification and business-data transmission are not accepted.
- 日期：2026-10-11 / Date: 2026-10-11.
- 依据：负责人在 V2.4 决策门之后的明确选择；当前实施状态只见 [CURRENT_SCOPE](../project-rules/CURRENT_SCOPE.md) / Basis: Owner's explicit post-gate choices; implementation status is owned by [CURRENT_SCOPE](../project-rules/CURRENT_SCOPE.md).

## 决定 / Decision

1. **D143**：首批固定候选为 OpenAI API 与 DeepSeek API。Provider Port 不能接受任意用户输入 URL。模型 ID、价格、Responses Schema、账号可用性、开发者条款及数据保留必须在真实调用资格验收时重新核对。选择厂商不等于许可发送真实业务资料。
2. **D144-A**：真实 API 的首次连通性和能力验证只使用合成内容；无密钥时使用假 Provider 的确定性测试。任何真实业务资料外发仍需独立范围授权和逐次输入确认。
3. **D145-A**：第三个 AI Action 只做“关键事实卡”提取，字段为事实、可选对象/时间和明确引用；不扩大成任意字段抽取或自动写入人工经验。
4. **D146-A**：以峰时、未命中缓存价格估算；单次请求估算上限 US$0.50，合成验收活动总预算上限 US$5。估算不是服务端硬性计费上限；超出预算或价格参数失效时停止，不静默重试。

1. **D143**: OpenAI API and DeepSeek API are the initial fixed candidates. The Provider Port accepts no user-supplied arbitrary URL. Recheck model IDs, price, Responses schema, account access, developer terms, and data retention at live qualification. Selecting vendors does not authorize real business-data transmission.
2. **D144-A**: First live connectivity and capability checks use synthetic material only; deterministic fake-provider tests work without keys. Real business-data transmission needs separate scope authorization and per-request input confirmation.
3. **D145-A**: The third AI Action is limited to key-fact cards: fact, optional subject/time, and explicit citations. It is not arbitrary extraction or automatic promotion into human experience.
4. **D146-A**: Estimate with peak, uncached rates; cap estimated cost at US$0.50/request and the synthetic acceptance exercise at US$5. Estimates are not provider-side hard billing caps; stop on stale pricing or exhausted budget and never silently retry.

## 实施 Gate / Implementation gate

生产配置默认关闭真实 Provider 外发。只有账号持有者配置 Windows Credential Manager 凭据、完成合成 API 试验，并审核当时的模型能力、条款、留存、价格及打包行为后，才可单独放开对应 Provider。OpenAI `store:false` 不是零留存承诺；DeepSeek 开发者平台的留存条件仍需账号/合同层面核验。两个 Provider 必须分别验收，不能因 API 形式相近而互相继承结论。

Production configuration keeps live egress disabled by default. The account owner must configure credentials in Windows Credential Manager, run synthetic API trials, and review current model capabilities, terms, retention, prices, and packaged behavior before enabling each Provider. OpenAI `store:false` is not a zero-retention promise; DeepSeek developer-platform retention still needs account/contract review. Qualify each Provider independently despite similar API shapes.

核验入口 / Verification references:

- [OpenAI models and pricing](https://developers.openai.com/api/docs/models)；[Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)；[data controls](https://developers.openai.com/api/docs/guides/your-data).
- [DeepSeek models and pricing](https://api-docs.deepseek.com/quick_start/pricing/)；[Responses API](https://api-docs.deepseek.com/api/create-response/)；[Open Platform Terms](https://cdn.deepseek.com/policies/en-US/deepseek-open-platform-terms-of-service.html).

## 现成 SDK 优先（2026-10-12） / Existing SDK first (2026-10-12)

负责人明确要求 API 接入优先使用现成、维护中的方案；只有所需能力经验证不适配时，
才自行实现 HTTP 细节。V2.4 首选评估 OpenAI 官方 Python SDK：OpenAI 使用默认
端点，DeepSeek 仅使用官方公布的固定 `base_url`；PIG 原有 Provider Port、
密钥存储、逐次输入预览、预算、引用和状态边界继续保留。不得把任意 URL 输入框
或 SDK 默认重试策略直接暴露给用户。SDK 的超时、重试、重定向、异常映射、
结构化输出差异和打包体积须在合成测试中验证；不适配时才保留范围受限的自写
Transport。此原则本身不批准新增依赖、真实 API 请求或生产外发。

The owner explicitly prefers an existing, maintained API integration; hand-written HTTP is a
fallback only after a required capability is shown incompatible. First evaluate the official
OpenAI Python SDK for V2.4: use its default OpenAI endpoint and DeepSeek's published fixed
`base_url`, while retaining PIG's Provider Port, credential store, per-request preview,
budget, citation, and state boundaries. Do not expose arbitrary URLs or inherit the SDK's
default retry behavior without review. Synthetic checks must cover timeouts, retries,
redirects, error mapping, structured-output differences, and package size. This preference
alone does not approve a new dependency, a live API request, or production egress.

## SDK 运行时选择（2026-10-13） / Runtime SDK selection (2026-10-13)

负责人随后明确要求完成 API 接入开发。依据无网络合成评估，运行时采用 OpenAI 官方
Python SDK `>=3.29,<3.30` 服务两个固定 Provider；DeepSeek 只使用其官方固定
`base_url`。PIG 在 SDK 的响应读取边界执行实际 2 MB 字节上限，请求未压缩响应
并拒绝意外压缩响应；关闭自动重试与重定向，显式设置超时，并将 SDK 异常转换为
不泄露正文或密钥的领域错误码。
这取代前述“仅评估、不加入依赖”的阶段状态，不取代独立的真实 Provider 资格、
业务资料外发与生产开关 Gate。

The owner subsequently authorized completing the API integration. Based on the networkless
evaluation, runtime uses the official OpenAI Python SDK `>=3.29,<3.30` for both fixed
providers; DeepSeek uses only its documented fixed `base_url`. PIG enforces the actual
2 MB response-byte limit at the SDK read boundary, requests an uncompressed body and rejects
unexpected compression, disables automatic retries and redirects, sets an explicit timeout,
and maps SDK exceptions to domain error codes that reveal neither
content nor credentials. This supersedes the earlier evaluation-only dependency status, not
the separate gates for live-provider qualification, business-data transmission, or production
egress enablement.
